Quick update on what I’ve been building. The idea is world coprocessors:
structured domain models that sit next to an LLM and make it correct in a
specific area without retraining or LoRA.

Think of it as an ontology that acts as a coprocessor. Instead of stuffing text
chunks into a prompt and hoping the model reasons correctly, we build an
explicit graph of entities, relations, and constraints, then use it to guide
generation with a verifiable control packet. OCTO attaches at inference time as
a control-plane layer between the user query and any LLM, replacing brute-force
nearest-neighbor retrieval over massive embedding corpora with a compact
structured world model that deterministically grounds generation in domain truth.

I now have two concrete proofs:

1) Live SQL on a real database. We built a SQLite Pagila-style database and asked
 four natural-language questions that require multi-table joins — for example,
 “How many actors have appeared in comedy films?” That needs the full chain
 actor → film_actor → film → film_category → category.

 Results vs. a real keyword-retrieval baseline:

 +------------------------+--------------+---------+
 | Metric | RAG baseline | OCTO |
 +------------------------+--------------+---------+
 | Exact result match | 0 / 4 (0%) | 4 / 4 (100%) |
 | Execution success | 3 / 4 (75%) | 4 / 4 (100%) |
 +------------------------+--------------+---------+

 These are observed numbers, not estimates. The demo creates the database,
 generates SQL from OCTO and the baseline, executes all three versions (gold,
 OCTO, RAG), and compares result sets.

2) Spider 2.0 Lite public benchmark. We evaluated OCTO on 135 real local-SQLite
 questions across 30 distinct schemas. Table recall @ top-8 is 86.2%:

 +-----------------------------+--------+
 | Metric | OCTO |
 +-----------------------------+--------+
 | Tasks evaluated | 135 |
 | Distinct SQLite schemas | 30 |
 | Avg. table recall @ top-8 | 86.2% |
 | LLM calls | 0 |
 +-----------------------------+--------+

 The keyword-only baseline scores the same 86.2% on table recall because
 Spider table names are strong signals, so I’m not claiming magic there. The
 point is that OCTO gives the same retrieval quality inside a structured,
 auditable world model — and the live-SQL demo shows where that structure
 wins (exact join paths that keyword retrieval misses).

Limitations I’m being upfront about: the Pagila database is synthetic, the
questions are curated to require joins, and the SQL generator is deterministic
rather than an LLM. The Spider demo measures table selection, not full query
execution. The point is to prove schema-grounding at scale, not claim we’ve
solved all of NL-to-SQL.
