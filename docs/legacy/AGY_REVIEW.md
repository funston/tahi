## Executive Summary & Peer Review Verdict

While the linked HTML artifact ([`docs/dashboard.html`](file:///home/rich/share/work/tahi/docs/dashboard.html)) presents a compelling narrative contrasting Plain LLM vs. RAG vs. TAHI across three benchmark tasks, an in-depth peer review of the underlying codebase, benchmark scripts, and historical audit logs reveals **severe methodological flaws, circular logic / tautologies, data leakage in the feedback loop, hardcoded shortcuts, and underlying architectural defects**.

To the team's credit, internal audit documents (such as [`HANDOVER_CRITICAL_REVIEW.md`](file:///home/rich/share/work/tahi/docs/legacy/HANDOVER_CRITICAL_REVIEW.md) and [`test_graph_retrieval.py`](file:///home/rich/share/work/tahi/tests/test_graph_retrieval.py)) candidly acknowledge several of these issues. However, when evaluating the claims as presented to external stakeholders, **the current benchmarks cannot be accepted as valid scientific proof of graph-based LLM reasoning.**

## 1. Breakdown of Specific Benchmark Flaws

### Flaw 1: MetaQA 3-Hop Test (Test 1) — Direct Answer Key Leakage in Feedback Loop
* **Claim:** TAHI achieves 78/100 on MetaQA 3-Hop while RAG gets 2/100 and Plain LLM gets 1/100.
* **Code Inspection:** [`scripts/metaqa_loop_tahi.py`](file:///home/rich/share/work/tahi/scripts/metaqa_loop_tahi.py#L113-L125)
* **Mechanism:**
  ```python
  def diff(ans: set[str], supported: set[str]) -> str | None:
      bad = sorted(ans - supported)
      miss = sorted(supported - ans)
      ...
      if miss:
          out.append(f"- IN the graph, you omitted: {', '.join(miss)}")
      return "\n".join(out)
  ```
  In MetaQA 3-hop questions, `supported` is computed via `chain_endpoints()` by following the 3-hop relation chain on `MetaQAGraph`. On MetaQA, **the supported endpoints from the 3-hop chain ARE the exact gold ground-truth answer set.**
  
  When `diff()` runs, `miss` equals `gold - ans`. The prompt sent to the LLM during the correction loop explicitly says:
  > *"A knowledge graph was checked. Findings: - IN the graph, you omitted: [EXACT MISSING GOLD ENTITIES]. Give a corrected answer."*

* **Reviewer Finding:** The "78/100" score does not measure LLM reasoning or graph integration. The feedback prompt literally hands the LLM the exact missing ground-truth entity names in plain text, turning the LLM into a basic text copy-paster.

### Flaw 2: Legend Traversal Test (Test 3) — Hardcoded Bypass & Circular Definition
* **Claim:** RAG writes non-existent routes 56 times out of 100, whereas TAHI writes non-existent routes only 1 time out of 100.
* **Code Inspection:** [`scripts/legend_multihop.py`](file:///home/rich/share/work/tahi/scripts/legend_multihop.py#L86-L105) and [`scripts/legend_multihop.py`](file:///home/rich/share/work/tahi/scripts/legend_multihop.py#L197-L200)
* **Mechanism:**
  1. **Dataset Selection Tautology:** `build_questions()` filters the test dataset to include **only** cases where `len(uniq) == 1` (i.e. exactly one route exists from start to target).
  2. **Hardcoded Bypassing of the LLM:** In the TAHI execution loop:
     ```python
     routes = sorted({f"{p1}.{want}" for p1, tgt in lm.neighbours(start) if want in lm.properties_of(tgt)})
     if len(routes) == 1:
         tahi = routes[0]
     ```
     Because every question was pre-filtered to have `len(routes) == 1`, `tahi` **always takes the python shortcut `routes[0]` and completely bypasses the LLM.**

* **Reviewer Finding:** In Test 3, TAHI's score is generated by 100% hardcoded Python graph traversal logic without ever calling an LLM. While the dashboard box notes that the exact-match score was removed due to tautology, citing "1 out of 100 invalid routes" for TAHI vs 56 for RAG masks the fact that TAHI did not use an LLM at all for this arm.

### Flaw 3: EnterpriseRAG-Bench — Pre-Registration Kill Criterion Triggered & Architectural Bugs
* **Pre-Registration:** In [`benchmarks/PREREGISTRATION_enterprise_rag.md`](file:///home/rich/share/work/tahi/benchmarks/PREREGISTRATION_enterprise_rag.md#L53-L59), the project pre-registered a strict kill criterion:
  > *"If `tahi_l1` − `rag` on the primary metric has a 95% CI that includes zero at n=170, the structural thesis is **not supported** on enterprise multi-source QA."*
* **Empirical Execution Result:** In [`benchmarks/results/enterprise_rag_full.md`](file:///home/rich/share/work/tahi/benchmarks/results/enterprise_rag_full.md#L41):
  ```
  tahi_l1[structural] vs rag[structural] | +0.0078 | [-0.0087, +0.0253] | NOT SIGNIFICANT (includes zero)
  ```
* **Architectural Root Cause (D1 & D2):** The project's unit test suite contains explicit RED tests in [`tests/test_graph_retrieval.py`](file:///home/rich/share/work/tahi/tests/test_graph_retrieval.py#L10-L17) documenting why TAHI failed to beat RAG on enterprise documents:
  1. **Defect D1 (Graph edges never traversed during retrieval):** [`src/tahi/world_state.py`](file:///home/rich/share/work/tahi/src/tahi/world_state.py) ran standard ANN dense search first, then hydrated edge metadata *after* top-k selection. None of the 956,232 graph edges generated candidate documents. "Graph retrieval" was just standard vector search.
  2. **Defect D2 (Entity pollution of document index):** Non-document entity nodes (`space::`, `person::`, `ticket::`) competed with documents for top-k vector slots, reducing effective document recall from `0.408` down to `0.331`.

### Flaw 4: Hetionet Benchmark — Confounded Prompts & Trivial Answer Key Lookups
* **Code/Doc Inspection:** [`docs/legacy/TAHI_PEER_REVIEW.md`](file:///home/rich/share/work/tahi/docs/legacy/TAHI_PEER_REVIEW.md#L196-L208)
* **Mechanism:**
  - In earlier Hetionet bio-trials, Arm C (RAG) used the prompt: `"Answer using only the knowledge base above."` while Arm E (RAG + Constrained) used: `"List every gene from the knowledge base above."`
  - The +20% gain reported for Arm E was confounded by the stronger instruction wording rather than graph-constrained sampling.
  - Furthermore, questions were generated directly from graph edges, meaning the lookup returned the exact gold answer key in the context window.

## 3. Real Accomplishments & Valid Engineering Assets

Despite the benchmark flaws, the project contains legitimate engineering value that should be preserved:

1. **Decode-Time Vocabulary Masking ([`src/tahi/validate/constrained.py`](file:///home/rich/share/work/tahi/src/tahi/validate/constrained.py)):**
   - The HuggingFace `LogitsProcessor` implementing trie/prefix-tree logit masking (`GraphConstrainedLogits`) is mathematically sound and guarantees 0% invented entity names at decode time without model fine-tuning.
2. **Internal Audit Rigor:**
   - The development team demonstrated exceptional self-awareness in internal documents ([`HANDOVER_CRITICAL_REVIEW.md`](file:///home/rich/share/work/tahi/docs/legacy/HANDOVER_CRITICAL_REVIEW.md), [`test_graph_retrieval.py`](file:///home/rich/share/work/tahi/tests/test_graph_retrieval.py)), explicitly identifying defects and pre-registering kill criteria.
3. **Evaluation & Bootstrap Infrastructure ([`src/tahi/eval/`](file:///home/rich/share/work/tahi/src/tahi/eval/)):**
   - `bootstrap_paired_delta` and exact set metrics provide robust statistical tooling once applied to clean, unconfounded datasets.

## 4. Peer Review Recommendations

1. **Fix Defect D1 & D2 in [`src/tahi/world_state.py`](file:///home/rich/share/work/tahi/src/tahi/world_state.py):**
   - Separate entity nodes from the document index so entity nodes do not pollute the document retrieval budget.
   - Implement true 2-hop graph expansion into the candidate pool *before* top-k selection, as specified in [`tests/test_graph_retrieval.py`](file:///home/rich/share/work/tahi/tests/test_graph_retrieval.py).
2. **Clean MetaQA Correction Loop:**
   - Modify [`diff()`](file:///home/rich/share/work/tahi/scripts/metaqa_loop_tahi.py#L113) so it does NOT hand the missing entity names to the LLM. Feedback should only state whether the graph validated the answer set or flag invalid entities, without revealing omitted gold entities.
3. **Run Standard Benchmarks via Vendored Harness:**
   - Execute the vendor evaluation harness in [`third_party/graphrag_bench_eval/`](file:///home/rich/share/work/tahi/third_party/graphrag_bench_eval/) on GraphRAG-Bench medical/micro datasets to benchmark against published baselines without custom prompt or test modifications.
